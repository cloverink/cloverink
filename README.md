## 🙃 Error Driven Development

<table>
<tr>
<td width="34%" align="center" valign="middle">

<img src="https://user-images.githubusercontent.com/26240331/163918543-041dcb66-979a-436c-8704-56f92bcc30e0.gif" width="250" alt="Just do it" />

</td>
<td valign="top">

**The fastest feedback loop in the industry.** No spec survives first contact with the runtime — so run it first.

1. **Run it.** The stack trace is the ticket.
2. **Read the error.** Every word. It already knows what's wrong.
3. **Fix exactly that.** Nothing more, nothing speculative.
4. **Repeat** until the only thing left to read is `0 errors`. Then ship.

> Tests tell you what you expected. Errors tell you what you missed.
> EDD is just TDD where the computer writes the failing test for you. 🙃

</td>
</tr>
</table>
